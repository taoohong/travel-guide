> 首版单台阿里云 ECS 即可（文档 60 章）。

## 1. 服务器结构

```text
阿里云 ECS
├── Nginx
│     /admin   → React 后台静态文件
│     /api     → NestJS（127.0.0.1:3000）
│     /static  → /data/travel-guide/uploads（图片）
├── NestJS（PM2 / systemd 托管）
├── PostgreSQL（本地实例 + 每日备份）
└── /data/travel-guide/uploads
```

**上传目录绝不放代码目录**：代码目录会被部署脚本覆盖或 `git clean`，
把用户图片放在里面等于给自己埋一颗定时炸弹。

## 2. 环境变量

`apps/api/.env`：

```bash
# ---- 运行模式 ----
# production：使用真实数据库与本地磁盘
# memory：内存模式，无需数据库，仅供本地联调
MODE=production
PORT=3000
APP_VERSION=0.1.0

# ---- 数据库 ----
DATABASE_URL="postgresql://travel:CHANGE_ME@127.0.0.1:5432/travel_guide?schema=public"

# ---- 鉴权 ----
# 必须至少 16 位；留空或过短时后端会**拒绝启动**
# 生成方式：openssl rand -base64 32
AUTH_SECRET="CHANGE_ME_TO_A_LONG_RANDOM_STRING"
# 小程序微信登录需要；从微信公众平台的小程序管理后台获取
WECHAT_APP_ID="wx..."
WECHAT_APP_SECRET="..."

# ---- 上传 ----
UPLOAD_ROOT_DIR=/data/travel-guide/uploads
# 客户端访问图片的前缀，需与 Nginx 的 /static 对应
STATIC_BASE_URL=https://api.example.com/static

# ---- CORS ----
# 多个用逗号分隔；留空表示允许全部（仅建议开发环境）
CORS_ORIGINS=https://api.example.com

# ---- 种子数据用 ----
DEMO_ADMIN_PASSWORD=CHANGE_ME
```

`.env` **不提交 Git**（已在 `.gitignore` 中）。仓库只保留 `.env.example`。

## 3. Nginx 配置

```nginx
server {
    listen 443 ssl http2;
    server_name api.example.com;

    ssl_certificate     /etc/nginx/ssl/api.example.com.pem;
    ssl_certificate_key /etc/nginx/ssl/api.example.com.key;

    client_max_body_size 6m;   # 比后端的 5MB 略大，让后端给出更友好的错误

    # ---- 后台静态文件 ----
    location /admin {
        alias /srv/travel-guide/admin/;
        try_files $uri $uri/ /admin/index.html;
    }

    # ---- 静态图片 ----
    location /static {
        alias /data/travel-guide/uploads;

        # 图片内容不会变（文件名带内容哈希），可以放心长缓存
        expires 30d;
        add_header Cache-Control "public, immutable";

        # 禁止执行任何脚本：即使有人上传了伪装成图片的文件
        location ~* \.(php|jsp|asp|sh|py)$ {
            deny all;
        }

        autoindex off;
    }

    # ---- API ----
    location /api {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;

        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Request-Id      $request_id;

        proxy_read_timeout 60s;
    }
}

server {
    listen 80;
    server_name api.example.com;
    return 301 https://$host$request_uri;
}
```

**`X-Request-Id` 传递很重要**：客户端报错时提供的 requestId 能直接在
NestJS 日志里定位到那一次请求。

## 4. 进程托管（systemd）

`/etc/systemd/system/travel-guide-api.service`：

```ini
[Unit]
Description=Travel Guide API (NestJS)
After=network.target postgresql.service

[Service]
Type=simple
User=travel
WorkingDirectory=/srv/travel-guide/apps/api
EnvironmentFile=/srv/travel-guide/apps/api/.env
ExecStart=/usr/bin/node dist/main.js
Restart=always
RestartSec=5

# 优雅退出：NestJS 已 enableShutdownHooks，SIGTERM 会先处理完在途请求
KillSignal=SIGTERM
TimeoutStopSec=30

# 安全加固
NoNewPrivileges=true
PrivateTmp=true

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now travel-guide-api
sudo systemctl status travel-guide-api
sudo journalctl -u travel-guide-api -f
```

## 5. 部署流程

```bash
# 1) 拉取代码
cd /srv/travel-guide && git pull

# 2) 安装依赖（CI=true 避免交互式提示）
CI=true pnpm install --frozen-lockfile

# 3) 质量门禁：任一失败即停止部署
pnpm typecheck
pnpm test
pnpm build                       # 构建 packages/*

# 4) 数据库迁移（只应用已有迁移，不改 schema）
pnpm api:prisma:deploy

# 5) 构建后端与后台
pnpm --filter @travel-guide/api run build
pnpm --filter @travel-guide/admin run build
sudo rsync -a --delete apps/admin/dist/ /srv/travel-guide/admin/

# 6) 重启并验证
sudo systemctl restart travel-guide-api
sleep 3
curl -fsS https://api.example.com/api/v1/health || echo "健康检查失败！"
```

小程序由 CI 构建后用微信开发者工具上传，不在服务器上编译。

### 小程序构建要点

```bash
pnpm miniapp:dev        # 编译到 apps/miniapp/dist（watch 模式）
pnpm build:miniapp      # 一次性构建
```

微信开发者工具**导入 `apps/miniapp` 目录**（不是 `dist`）——
`project.config.json` 里的 `miniprogramRoot: "dist/"` 会指向真正的产物。

CI 里需要注意的两点（本地构建时同样适用）：

1. **共享包必须被 webpack 转译**。
   `@travel-guide/*` 通过 pnpm 软链到 `node_modules/`，而 webpack 默认排除
   `node_modules`，导致共享包的 TS 源码被当普通 JS 解析并报
   `Module parse failed: Unexpected token`。
   已在 `apps/miniapp/config/index.ts` 的 `mini.compile.include` 中显式声明。
2. **Babel 预设必须显式安装**。
   `babel-preset-taro` 依赖 `@babel/preset-react` / `preset-env` / `preset-typescript` /
   `plugin-transform-runtime`，缺少时会报 `Cannot find module '@babel/preset-react'`。
   它们不是自动安装的传递依赖（pnpm 不做幽灵依赖），必须写进 `devDependencies`。

构建产物结构：

```text
apps/miniapp/dist/            约 520 KB
├── app.json / app.js / app.wxss      ← 全局（app.js 约 95KB）
├── pages/
│   ├── dashboard/          index.{js,json,wxml,wxss}
│   ├── destination-detail/
│   └── settings/
├── common.js      约 154KB  ← 共享包（core / api-client / constants）打在这里
├── taro.js        约 116KB  ← Taro 运行时
├── vendors.js     约 25KB
└── runtime.js
```

**验收点**：构建后 `dist/app.json` 中的 `pages[0]` 必须是 `pages/dashboard/index`，
且**不含** `tabBar` 字段（文档 90 章：不使用微信原生 tabBar）。

### ⚠️ 不要修改 `babel.config.js` 里的 `useBuiltIns`

`apps/miniapp/babel.config.js` 只保留三个必要选项：

```js
presets: [['taro', { framework: 'react', ts: true, compiler: 'webpack5' }]]
```

`babel-preset-taro` 的默认值是 `useBuiltIns = false`、`modules = false`，
**这两个默认值不能动**：

| 选项 | 若改成 | 后果 |
|---|---|---|
| `useBuiltIns: 'usage'` | 让 `@babel/preset-env` 注入 core-js polyfill | 每个模块顶部被插入 polyfill import，**打乱 webpack 模块求值顺序** |
| `modules: 'commonjs'`（或非 false） | 把 ESM 转成 CJS | webpack 无法静态分析，tree-shaking 失效、循环依赖变脆弱 |

前者会导致启动即崩：

```text
TypeError: Cannot read properties of undefined (reading 'taroDocumentProvider')
    at Module.document (...)
    at .../core-js-pure/internals/is-callable.js
```

原因是 `@tarojs/runtime` 还没完成导出，polyfill 代码就先执行了。
小程序端的 polyfill 由 Taro 运行时代理负责，**不需要 Babel 再插一层**。

改回默认值后包体从 653 KB 降到 520 KB，`core-js-pure` 相关代码完全消失。

## 6. 数据库

### 备份

```bash
# 每天 03:30 全量备份并保留 14 天
30 3 * * * /usr/bin/pg_dump -U travel -Fc travel_guide \
  | gzip > /data/backup/travel_guide_$(date +\%F).dump.gz \
  && find /data/backup -name 'travel_guide_*.dump.gz' -mtime +14 -delete
```

### 恢复演练（**每季度至少做一次**）

```bash
createdb travel_guide_restore
gunzip -c /data/backup/travel_guide_2026-09-20.dump.gz | pg_restore -d travel_guide_restore
psql -d travel_guide_restore -c 'select count(*) from "Country";'
```

**没有演练过的备份等于没有备份。**

### 关键约束检查

```sql
-- 确认签证唯一约束存在（写错会让不同护照的政策互相覆盖）
```

## 7. 磁盘与图片

### 容量估算

单张压缩后图片约 300～700KB。假定：

```text
1000 个用户 × 20 张照片 = 20000 张 × 500KB ≈ 10 GB
```

建议上传盘至少 100GB，并配置告警。

### 磁盘告警

```bash
# 使用率超过 85% 告警
df -h /data | awk 'NR==2 {gsub(/%/,"",$5); if ($5 > 85) print "DISK ALERT: " $5 "%"}'
```

### 清理孤立文件

数据库里已删除、但磁盘上还留着的图片：

```sql
-- 导出所有被引用的路径
select path from "MediaAsset"
union select path from "MemoryPhoto";
```

```bash
# 找出磁盘上不在引用列表中的文件（人工确认后再删除）
comm -23 \
  <(find /data/travel-guide/uploads -type f -printf '%P\n' | sort) \
  <(psql -At -U travel travel_guide -c 'select path from "MediaAsset" union select path from "MemoryPhoto"' | sort) \
  > /tmp/orphan-files.txt
wc -l /tmp/orphan-files.txt
```

## 8. 监控与日志

### 必看的日志字段

NestJS 的结构化日志包含：

| 字段 | 用途 |
|---|---|
| `requestId` | 与客户端报错对账 |
| `method` / `path` / `status` | 定位异常接口 |
| `durationMs` | 发现慢接口 |
| `code` | 按业务错误码聚类（例如 `DUPLICATE_CONTENT` 突增说明去重逻辑有问题） |

### 关键告警

| 指标 | 阈值 | 含义 |
|---|---|---|
| 5xx 比例 | > 1% 持续 5 分钟 | 程序缺陷或依赖故障 |
| P95 响应时间 | > 2s | 数据库慢查询或连接池不足 |
| 磁盘使用率 | > 85% | 图片把盘写满 |
| `/health` 返回 degraded | 连续 3 次 | 数据库不可用 |
| 内容健康度「90 天未确认」 | > 5 条 | 内容运维欠债 |

## 10. 回滚

```bash
# 代码回滚
cd /srv/travel-guide
git log --oneline -5
git checkout <上一个可用版本>
CI=true pnpm install --frozen-lockfile
pnpm --filter @travel-guide/api run build
sudo systemctl restart travel-guide-api

# 数据库迁移回滚（谨慎：会丢数据，先备份）
pg_dump -U travel -Fc travel_guide > /data/backup/pre-rollback.dump
cd apps/api && npx prisma migrate resolve --rolled-back <migration_name>
```

**迁移只做加法**：新增可空字段、新增表、新增索引；
删除字段或改类型必须先发一版兼容代码，确认无回滚需求后再清理。
这样绝大多数故障都可以用「回滚代码」解决，不需要回滚数据库。
